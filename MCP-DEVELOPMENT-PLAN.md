# План разработки PowerShape MCP

Актуальный приоритет: 18 октября 2026. **P0 в обычном чате Codex принят пользователем**: «Принимаю P0, продолжай К8–К11». Продолжить завершение универсального **MCP v1 до К11**. P0 не заменяет приёмку v1. Технологический модуль — отдельный последующий продукт и клиент общего MCP.

## Ближайшая поставка P0

Одна законченная функция: прочитать представительную модель → открыть собственную копию → явно определить одно тело SOLID → перенести на заданный вектор WORLD → независимо проверить → SaveAs в новый файл → открыть отдельную копию результата → независимо проверить сохранность.

Пользователь выбрал сохранённую модель; её полный путь закреплён только в локальном состоянии. В публичном сценарии используется псевдоним `USER_MODEL.psmodel`. Состав, доступные измерения и единицы проверены в завершённом сценарии P0; результат принят пользователем. Исходник не открываем для правки и не перезаписываем. Испытание на кубе подтверждает базовый механизм, но не пользовательскую приёмку P0.

| Шаг | Результат | Контроль пользователя / условие перехода |
|---|---|---|
| P0.1 — точный сценарий | Модель, один явный SOLID, WORLD-вектор, единицы, ожидаемые изменения, предел числа окон и условия остановки | Пользователь видит сценарий. Если тел несколько, цель выбирается явно; неизвестные свойства не подменяются предположением |
| P0.2 — обычное подключение | Проверенная пара Native 0.37.0-dev / SDK 0.43.0-dev; отдельный сервер `--read-only`; конкретный diff конфигурации, резерв и возврат | Перед изменением конфигурации/перезапуском — согласие. После: версии и каталог проверены именно из обычного чата; изолированный SDK-процесс этого не доказывает |
| P0.3 — полный реальный проход | Один перенос → независимая проверка → один SaveAs → проверка → одно открытие копии результата → проверка | Одно согласование всей последовательности на собственной копии. Исходник сохранён, новый файл существует, пользователь может посмотреть итог и повторить по короткой инструкции |
| P0.4 — воспроизводимый кандидат | Комплект запуска с хешами и версиями, краткая инструкция, диагностика, возврат конфигурации, необходимые проверки | Демонстрация через обычный Codex на выбранной модели и пользовательская приёмка P0. Только после этого расширение операций |

P0 поддерживает одну выбранную сущность SOLID и перенос в WORLD. Поворот, масштаб, экспорт, пакетные/смешанные наборы и расширенное восстановление не являются условиями P0. Предлагать WORLD [1,2,3] в подтверждённых миллиметрах; если единицы/геометрия/цель не подтверждаются — остановиться до изменения и уточнить сценарий.

Конкретный обзор подключения, полный согласуемый проход и короткая инструкция: [P0-USER-SCENARIO.md](P0-USER-SCENARIO.md). Готовность/доказательства комплекта фиксируются в PROJECT-STATE.md; подготовленный сценарий ещё не является разрешением на его запуск.

**Результат 16 октября:** сценарий согласован и технически пройден через обычный SDK-клиент на `USER_MODEL.psmodel` (один SOLID). P0.1–P0.3 подтверждены; P0.4 — кандидат P0-20261016.1 и [инструкция](docs/P0-QUICKSTART.md), пользовательская приёмка ожидается. Не повторять завершённый сценарий. К8–К11 остаются открытыми; новое расширение операций — после приёмки P0.

Новые окна: N → N+1 при открытии начальной собственной копии → N+2 при открытии отдельной копии сохранённого результата; N читается заново перед запуском. Точное начальное N закрепляется в локальном согласовании, не переносится из старого отчёта. Исходный файл не открывается отдельным дополнительным окном. Измерения первой собственной копии сверяются с дисковым источником и журналом копирования; это не полная проверка топологии исходника.

Ориентир — один сфокусированный рабочий день для P0 с пересмотром после проверки подключения и представительной модели. Это целевой лимит, не обещание срока v1. Ожидание согласования/переподключения и проблемы реальной модели учитываются отдельно.

## Порядок после P0

Сохранить уже выполненные К1–К8 и применимые доказательства. Закрыть оставшиеся строки К8 по одной функции (параметризованные наборы/типы, поворот, равномерный масштаб, организация), затем К9 (плоскости/массивы/пересечения/обмен/наблюдение/owned close), К10 (вся матрица), К11 (выпуск и приёмка). Для каждой новой операции применяются К7 и защита от повтора неизвестного результата.

До приёмки P0 начало новых направлений rotate/scale/export/расширенного recovery отложено, кроме исправлений, необходимых выбранному сценарию. Существующие реализации и исследования сохраняются. Подготовка translation-set guards не продолжалась; завершённые команды не повторяются.

## Рабочий цикл и ограничения

Одна законченная пользовательская функция одновременно: небольшое изменение → целевые проверки кода/готовности пакета → ранняя проверка PowerShape на собственной копии → независимая проверка → необходимые регрессии → фиксация состояния. Синтетические тесты сохраняются. Полный прогон — после завершённого блока при изменении кода или обоснованном риске; неизменённая ревизия использует прежние результаты после проверки хешей и применимости.

Небольшое улучшение CI подготовлено 17 октября: feature push отключён, проверки PR/main push/manual сохранены; устаревшие прогоны отменяются только внутри того же PR и workflow. Состав проверок не сокращён. Локальная проверка YAML пройдена; применение и серверная проверка — через PR. Это не отдельный проект и не причина пересобирать работающий runtime.

Перед CAD — свежие процесс/сеанс/документ/контекст и явная цель. Источники и отдельный checkpoint защищены. При неизвестном исходе остановка, журнал, независимая сверка; нет retry, inverse/Undo или очистки по догадке. Мышь только по отдельному согласию. Read-only не выбирает/активирует/сохраняет и не создаёт screenshot. `releases/P2.6` сохраняется; сборка в staging; не создавать вторую панель/worker.

Использовать dotnet-mcp-builder и Autodesk Product Help (PowerShape 2023, разрешён en_US). Не заменять подтверждённую совместимую пару обновлением SDK без необходимости P0. Raw-единицы не называть мм без проверки; bounds/COG/объём/площадь не доказывают полную топологическую эквивалентность.

Каждый завершённый блок имеет ограниченный PR, проверки и ограничения; raw-модели, конфигурация и доказательства остаются локально. Текущий результат — в PROJECT-STATE.md; ближайшие действия — только в NEXT-WORK.md.
