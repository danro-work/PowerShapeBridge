# К8: создание рабочей системы координат на собственной копии

Состояние 15 октября 2026: одна реальная WORLD workplane создана и независимо
проверена, включая новое SDK-подключение без replay. Native 0.35.0-dev,
SDK 0.41.0-dev. STATUS-K8-OWNED-WORKPLANE-LIVE.md. Сохранение и общая К8 не приняты.

## Граница операции

`prepare_owned_workplane` принимает свежую привязку собственной рабочей копии
и ровно семь параметров: `originWorldRaw[3]`, `zAxis[3]`, `yAxis[3]`,
`coordinateFrame=world`, `lengthUnits=document_raw`, `activeAfter=world`,
`mode=create_new`. Z и Y уже должны быть ортогональными единичными векторами.
Нормализация, произвольные команды, имя, слой и путь не принимаются.
Исходное выделение пустое, исходная система мировая. Подготовка CAD не меняет.

`execute_owned_workplane` выполняет явно объявленные два шага:

1. Один `CreateWorkplane`: начало XYZ, вектор Z, вектор Y относительно WORLD.
   PowerShape сам активирует созданную систему.
2. Только после положительного Int32 результата и чтения положительного
   ActiveWorkplane — один `ActiveWorkplane=0`. Это согласованная часть операции.

При исключении или неподтверждённом результате первого шага второй не выполняется.
Имя и слой создаваемой системы выбирает PowerShape по текущим настройкам создания.
Существующие объекты не переносятся, выделение не меняется, сохранения нет.

## Проверка и защита

Перед вызовом повторно проверяются процесс, документ, окна, привязка, владение,
сохранённые байты, checkpoint, система координат и выделение. Срок привязки 300с
не продлевается. Одноразовое намерение потребляется до отправки; native сохраняет
claim, блокировку копии и неизменяемый журнал. Отдельная квитанция создания
предшествует возврату в WORLD. Общая запись возврата требует обоих шагов.

Результат должен содержать ровно одну новую WORKPLANE(type54), правильные WORLD
начало/Z/Y, мировую активную систему и прежние наблюдаемые объекты, их свойства,
габариты, старые рабочие системы и сохранённые файлы.
`verify_owned_workplane` использует новые независимые чтения после команды,
повторяет проверки через native getters и освобождает только свою блокировку.
Свойства и габариты не доказывают полной топологической эквивалентности.

После переподключения `adopt_owned_workplane_execution` выдаёт только ссылку для
проверки исходного исполнения. Она не позволяет повторить создание.
`inspect_operation_recovery` читает записанные доказательства, не подключается
к CAD и не выдаёт разрешений на изменение или снятие блокировки.
Неизвестный исход сохраняется; повтор, Undo и автоматическое восстановление запрещены.

Инструменты явно зарегистрированы в `ToolCatalog.Create` через
`OwnedWorkplaneTools.Create(session)`. Нужен отдельный opt-in
`ownedWorkplanesExperimental=true` вместе с entitySets/workingCopies/documentBindings.
В read-only сервере все четыре инструмента отсутствуют. Старый Python-каталог
их не публикует. Общие ядро и технологический клиент остаются разделены.

## Квалификация

66 целевых .NET проверок (24 workplane и 42 recovery), 12 native controls/faults,
проверки допуска enabled/disabled, сквозной SDK→native file protocol с одной
имитацией создания и переподключением без повтора — passed.
Положительный контроль API выполнен один раз по отдельному разрешению;
55hash file audit и дополнительный passive COM read passed. После него141целевых
.NET checks/0skips и полный workplane runner с transport faults/audits passed.
Полная CI выполняется после этого реального результата согласно AGENTS.md.
