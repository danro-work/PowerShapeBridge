# PowerShape MCP — первый пользовательский прототип P0

Кандидат **P0-20261016.1**. Технически проверен через обычное подключение Codex на пользовательской детали, 16 октября 2026. Пользовательская приёмка ожидается. Это промежуточная поставка; К8–К11 полного универсального v1 не закрыты.

## Что уже можно сделать

Прочитать модель, создать собственную копию сохранённого `.psmodel`, перенести одно явно определённое тело SOLID на заданный вектор WORLD в миллиметрах, проверить результат, сохранить в новый файл, открыть отдельную копию результата и проверить сохранность.

В проверенном примере использовалась представительная деталь пользователя. Перенос `[+1,+2,+3]` мм сохранился после SaveAs и открытия копии. Исходный файл остался прежним.

## Обычный рабочий процесс

1. Оставьте PowerShape и единственную панель Bridge открытыми. В Codex должны быть подключения `powershape_bridge` и `powershape_bridge_readonly`.
2. Попросите проверить версии: SDK **0.43.0-dev**, Native **0.37.0-dev**. Основной список содержит 28 разрешённых инструментов, отдельное чтение — 8. Чтение не выбирает объекты, не переключает документ, не сохраняет и не создаёт screenshot.
3. Напишите, например: «Подготовь сценарий: создай свою копию сохранённого файла [полный путь], перенеси единственное тело WORLD на X=1, Y=2, Z=3 мм, отдельно сохрани и проверь результат после открытия копии. Сначала покажи модель, цель, параметры и новые файлы». Если тел несколько — укажите одно явно.
4. Проверьте сценарий и разрешите его целиком. Для нового запуска создаётся новая копия; старые команды и неизвестные результаты не повторяются.
5. Посмотрите активную копию результата в PowerShape. Codex выдаёт отдельный сохранённый файл и отчёт проверок. Исходник не перезаписывается. Обычно добавятся два окна; начальное количество проверяется перед действием.

## Ограничения P0

Подтверждены одна сущность SOLID, WORLD, миллиметры и пустое выделение. Цель проверяется перед командой. Неподдержанные единицы/свойства, неоднозначный выбор или смена документа прекращают сценарий до следующего изменения. Повороты, масштаб, экспорт, несколько тел за один запрос, локальные оси и технологические правила ещё не входят в пользовательскую приёмку P0.

При тайм-ауте или неизвестном исходе нельзя автоматически повторить команду, применить обратный перенос, Undo, дополнительное сохранение или открытие. Сначала читаются исходный журнал и модель. Проверенные габариты/центр/объём/площадь не доказывают полную топологическую эквивалентность. Raw-площадь и raw-объём не объявляются мм²/мм³ без проверки единиц.

## Проверенный комплект и возврат

Локальный комплект: `work/P0-candidate-370-430/`. В нём 39 точных файлов квалифицированного SDK, настройки двух подключений, `manifest.json`, инструкция, диагностический пассивный reader и `bundle-manifest.json` с SHA. Базовый runtime остаётся в совместимом `releases/P2.6`; никакой сборки поверх launcher не выполняется. Исходный исполняемый код — ревизия `e7387d99b6969f0079fa2fc74d4da2f689a2d37d`, ModelContextProtocol 2.2.0, Hosting 10.0.12, .NET 10.

Для другого компьютера нужны PowerShape 2023 с доступным COM и .NET 10; пути подключения заменяются на его собственные. Такая установка требует отдельной проверки, текущая демонстрация её автоматически не квалифицирует. Это локальный кандидат, не опубликованный релиз v1.

Если инструменты отсутствуют, сначала проверить фактически загруженные версии и переподключить MCP в Codex. Если чтение не отвечает, не запускать вторую панель/worker и не повторять мутацию; проверить состояние Bridge, очередь и исходный request ID. Недоступность дополнительного диагностического COM-доступа не равна поломке PowerShape.

Полный резерв прежней конфигурации создан рядом с пользовательским `config.toml`; путь и хеши — в `config-switch-receipt.json` комплекта. Возврат через `configure-codex.py --restore` допускается после остановки MCP и проверки, что конфигурацию после установки не меняли. Скрипт откажется затереть более поздние настройки. Затем переподключить MCP. Возврат настройки не отменяет CAD-изменения и не закрывает документы.

Публичная сводка — в PROJECT-STATE.md; точные машинные пути и доказательства — только в локальном work/P0-local-state-20261017.md; полный согласованный сценарий — в P0-USER-SCENARIO.md.
