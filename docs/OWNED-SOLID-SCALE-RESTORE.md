# Current access to an already verified scaled copy

`restore_owned_solid_scale` renews current connection access to an existing owned saved-reopen single-SOLID copy after a successful qualified scale. It is full-only and gated by `ownedSolidScaleRestoreExperimental`, false by default. Strict Native, SDK and Python readers require qualified scale, saved reopen, candidates, working copies and document bindings. `ToolCatalog` explicitly registers `ScaleRestoreTools.Create(session)`; the read-only catalog excludes this tool.

The four required inputs are the original successful scale verifier request ID, its 64-character SHA256, a fresh candidate document handle and a fresh one-use active window choice. Historical receipts establish provenance. They do not restore old handles. The path checks the original successful saved OPEN and binding, scale execution and verifier, thirteen-phase/once/journal proofs, ownership and retained source/seed/working/checkpoint files, absence of fences, current process/document/windows and post-scale observations. It remeasures transformed source witnesses and bounds with the unchanged bounded document tolerance.

The Native observer reuses the scale verifier's geometry and immutable-phase checks in a separate restoration mode. That mode requires the already successful terminal journal and absence of the fence; it cannot append success, remove a fence or resume an interrupted operation. It creates a new frozen diagnostic, current-observation report and passive binding. Only after independent SDK raw/report/history checks are current copy/binding leases issued. Cancellation, timeout, late results or rejected proof issue no usable authority. No OPEN, scale, selection, activation, save or original-journal repair occurs during restoration. Fake contexts cannot issue current access.

The profile is deliberately limited to the original-named, currently active Working copy whose pre-scale binding came from successful saved-reopen verification. Other origins, changed context/content/windows, fenced copies and renamed SaveAs results require separate contracts. The result explicitly says `geometrySaved: false`. A subsequent SaveAs must use a new owned target and its own independent verifier.
