# Owned saved-copy close over MCP

The full STDIO server now exposes `execute_owned_saved_copy_close` and `verify_owned_saved_copy_close` behind the default-false `ownedSavedCopyCloseExperimental` flag. `ToolCatalog` registers them explicitly with `SavedCopyCloseTools.Create(session)`. The dedicated configuration includes the saved-reopen, save, save-target, working-copy open, entity-set, working-copy and document-binding prerequisites. Native, SDK and Python configuration readers reject non-boolean flags and missing prerequisites. Read-only mode excludes both tools.

This is a narrow experimental profile: an independently verified saved-reopen Working copy with its original owned filename, one view, the active last model window, unchanged immutable saved-source/seed/working/checkpoint files, WORLD context and empty selection. Its canonical saved source must remain open. The live qualification used one SOLID in a millimetre document. Arbitrary documents, unsaved edits, renamed saved results, middle windows and multiple views are outside this profile.

The workflow is current saved-source restoration, filesystem-only copy preparation, one saved OPEN and independent verification issuing a current connection binding. Obtain fresh candidate/window observations, explicitly choose `disposition: "discard_owned_saved_copy"`, execute once, then independently verify the result from fresh remaining-window observations. Historical artifacts establish provenance; they cannot substitute for the current binding and explicit disposable-copy decision. Execution consumes all CAD leases before IPC. The strict schemas reject extra fields. Closing does not issue a replacement edit binding.

Native execution validates provenance before COM attachment, holds the executor lock, freezes a bounded plan, claims the operation once and journals the exact qualified command. See [the original core qualification](OWNED-SAVED-COPY-CLOSE-CORE.md) for command semantics. Independent verification checks original receipt bytes, plan, claim, command-return event, every remaining window and protected files. It appends terminal success and releases only the matching fence. Cancellation, timeout, late or unknown outcomes prohibit automatic replay; a missing authoritative command return cannot be resolved by this verifier.

On 24 October 2026, Native 0.45.0-dev was installed with backup and one panel restart; staged SDK 0.51.0-dev ran the real STDIO route. One new copy was opened, independently verified, explicitly closed once and independently close-verified. Window count was 25 → 26 → 25; all original windows remained. Independent audit verified 251 protected files, 25 previous saved files, new seed/working/checkpoint bytes and the six-event journal chain. No SaveAs, geometry change or mouse interaction occurred. This also exercised the corrected executor post-hash path left unqualified by the earlier core-only block. Ordinary Codex remains SDK 0.48; its configuration was not changed.

Validation: 42 Native guards plus marker refusal, 13 Python configuration cases, and the complete .NET regression of 961 tests passed. The initial targeted SDK run passed 17/18: one test incorrectly enumerated an intentionally absent request directory. After that fixture-only assertion correction, the failed case and official SDK success route passed, followed by the full regression. Initial failure artifacts are retained. The separate read-only catalog contains eight tools and neither close tool; full experimental catalog contains 61. These are scoped checks, not completion of the five-class K10 fault matrix or K11 acceptance. Full topology equivalence is not claimed.
