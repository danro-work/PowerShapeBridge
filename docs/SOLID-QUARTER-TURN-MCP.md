# К8: ограниченный поворот через MCP

20 октября 2026. Native0.38/SDK0.44 добавили отдельный путь для случая: один SOLID, единственный объект собственной рабочей копии, mm/factor1, +90° вокруг WORLD Z через начало. Native0.39/SDK0.45 расширяют этот путь до +90° или −90° с явно заданным центром оси WORLD Z. Другие оси, углы, наборы и типы пока отклоняются. Это ещё не вся К8 и не универсальный v1.

## Рабочий процесс

1. Прочитать активную модель, подготовить собственную копию и checkpoint; открыть её один раз и независимо проверить. Исходник защищён.
2. Получить наблюдаемый набор из одного тела, привязать собственный документ и создать пассивный план `prepare_rotation_plan` с явной мировой осью.
3. `prepare_owned_solid_quarter_turn` связывает план и документ, закрепляет face names/UV, проверяет читаемость точек/нормалей и сохраняет доказательства. CAD не изменяется.
4. `execute_owned_solid_quarter_turn` расходует короткое разрешение до отправки, затем существующий Native executor выполняет один RotateItem. Результат остаётся unverified и fenced.
5. После новых отдельных чтений `verify_owned_solid_quarter_turn` проверяет исходный receipt, контекст, журнал, владельца, файлы и прежние опорные измерения. Только после успеха журнал завершается и удаляется matching fence.

Native feature flag `ownedSolidQuarterTurnsExperimental` по умолчанию выключен. Требуются owned rotation/operation plans и их зависимости. SDK хранит точный SHA исходной подготовки и descriptor bundle в данной connection; даже согласованная подмена обоих файлов после выдачи handle не проходит. Общий пассивный `prepare_owned_rotation` сам по себе не выдаёт разрешение этого пути. Истёкшие, чужие и уже использованные handles не ставят новую команду в очередь. Unknown не повторяется и не компенсируется обратным поворотом.

Новые инструменты отсутствуют в серверном `--read-only`; прямые обращения также запрещены до IPC. Python legacy facade их не предоставляет. Регистрация SDK: `ToolCatalog.Create` включает `SolidQuarterTurnTools.Create(session)`, а `Program.cs` передаёт каталог в `.AddMcpServer(...).WithStdioServerTransport().WithTools(ToolCatalog.Create(session))`. JSON Schema запрещает произвольные paths/commands/дополнительные поля; описания и annotations заданы для каждого инструмента.

## Реальная проверка

Через настоящий SDK STDIO client, Native queue и одну установленную панель выполнены одно открытие новой собственной копии, ровно один поворот и независимая проверка новым COM-контекстом. Отдельный сервер чтения подтвердил текущий результат. Повторного сохранения и открытия сохранённого результата в этом блоке не было: предыдущий сценарий persistence уже прошёл и не повторялся. 199 защищённых файлов, исходник и checkpoint сохранились. Доказательства, точные IDs/пути и CAD-данные остаются локально.

Затем SDK0.44 появился в обычном Codex: версия, четыре новых tools, отдельный read-only и вызов +90° WORLD Z подтверждены на новой собственной копии с независимым verifier и файловым аудитом. Это отдельное подтверждение обычного клиентского пути, завершённые команды не повторяются.

Расширение Native0.39/SDK0.45 прошло раннюю реальную проверку −90° вокруг WORLD Z через явно смещённый центр: одно открытие новой собственной копии, один RotateItem, отдельный verifier и readonly confirmation. Независимый аудитор использовал прямую формулу поворота точек и нормалей, проверил точные габариты, invariants, хеши/журнал/claim/fence и защищённые файлы. Это staged SDK STDIO через установленную панель; обнаружение SDK0.45 обычным Codex проверяется отдельно. SaveAs/reopen этого результата не выполнялись. Native установлен с резервом и одним штатным перезапуском; первый sandbox-запуск установщика остановился до закрытия панели, файлы/резерв были сверены перед продолжением с обычными правами.

Публичные имена tools и регистрация прежние. Каталог SDK full48/read-only8; разрешённый каталог Codex full32/read-only8. Прежний scope +90°/начало сохранён для совместимости доказательств. Для signed/pivoted варианта scope выводится из закреплённых параметров и сверяется в подготовке, исполнении и verification; неподдержанная или ненормализованная ось не принимается как исполненная.

## Проверки и пределы

27 целевых SDK/transport cases проверяют режимы, знак/центр и pin исходного scope, целостность подготовки, запрет повтора после timeout, истечение/чужие handles и согласованную подмену receipt+descriptor. 25 Native boundary checks проверяют знак/центр/ось, тип/набор/инвентарь/единицы, строгий envelope и зависимости feature flag. Offline runner требует собственного marker и не создаёт COM-контекст. Он включён в `verify-sdk.ps1`. Регрессия и серверная CI текущего исходного блока фиксируются в PROJECT-STATE.md; результаты прежней ревизии не заменяют проверку новой.

Проверяются прежние восемь точек и нормали, COG, доступные raw invariants и габариты, а не полная B-rep/топологическая эквивалентность. Единицы площади остаются неизвестными, объём не объявляется мм³. Старый fenced отказ до изменения из предыдущего блока сохранён и не переподаётся. Ни установленный пакет, ни пользовательская настройка не публикуются на GitHub.
