# Separate recovery of a phase0-only curve-scale selection stop

Native0.64/stagedSDK0.70.1 add a separately gated, full-only recovery for the
specific [phase0 selection stop](CURVE-SCALE-SELECTION-STOP.md). It is not a
general unknown-operation recovery and does not continue or repeat the scale.
The public curve readers still require empty selection, as Autodesk specifies.
The neighboring SOLID and original complete curve control capture stay pinned.

Three tools are explicitly registered through
`Program.WithTools(ToolCatalog.Create(session))` and
`..CurveScaleStopRecoveryTools.Create(session)`: preparation, one execution and
independent verification. The default-off `curveScaleStopRecoveryExperimental`
flag requires stop inspection and owned selection. Read-only mode contains none
of these tools and cannot call them directly. No transport/packages change.

Preparation binds the immutable original failure/preparation/measurement,
returned phase0 and four-event unknown journal, original once claim/fence and
fresh positive native selected identity/document/owned-file/window context.
It creates a NEW narrow packet and connection-local one-use handle with the
original fresh inspection/listing expiry. It cannot renew the consumed scale
packet or issue general edit authority. Its only fixed command is
`SELECT CLEARLIST`, using the existing one-use selection program and writer.

Execution rechecks those proofs with retained ownership/byte/context leases.
It has a new claim, journal and secondary fence; the original mutation fence
remains present. Only one clear callback is admitted. A lost return or changed
postcondition stops with both fences/claims retained; no retry, inverse,
automatic cleanup, scale, SaveAs, OPEN, close or mouse is performed. Void Exec
return is recorded as `commandReturned=true`, not a fabricated native number.

The separate verifier requires that authoritative clear return, later fresh
inspection/listing, explicit double zero-count and direct inventory proof.
It does not infer empty selection from a null GetSelectedItems result. Only
then does it read complete original controls, tangent directions/magnitudes,
free flags and the original pinned SOLID descriptor twice. Observed properties,
saved files and windows must also match. Drift preserves the fences. Fake
contexts may produce sampled-match diagnostics but cannot release fences.

After real successful verification, the original fence bytes are archived and
a separate immutable resolution records selection recovered and scale not
successful. The recovery journal is completed; the secondary fence is released
first and the original matching fence last. The original failure receipt,
four-event unknown journal and consumed scale claim remain unchanged. Generic
mutations therefore remain gated through incomplete or crashed verification.

## Real qualification

On26October(MSK), one separately prepared clear returned, followed by a separate
Native/SDK verifier and the normal passive curve/SOLID reader. Four controls,
eight tangent directions/magnitudes,16free flags and all original SOLID samples/
normals/COG/bounds/raw metrics matched exactly. Independent Python also checked
the expected original coordinates,893protected files,28windows, both journals,
claims, archived fence and separate resolution. No scale/save/open/close/mouse
occurred. This is control/sample equality, not full continuous topology.

Initial SDK0.70 preparation was rejected before any clear because equivalent
Native `Z` and SDK `+00:00` expiry strings differed. The original Native packet
remained unclaimed. SDK0.70.1 compares exact absolute ticks with explicit zones;
it never extends the lease. The fix passed on the original Native bytes and
rejects even a one-tick extension. A NEW fresh recovery preparation was then
used; the earlier packet and failure remain preserved.

Targeted Native5/Framework-SDK9/SDK10/Python29, expirySDK8 and actual-preparation
byte proof passed before CAD; catalog88full/11readonly refused unknown handles
before queue submission. Full regression/post-CAD results and exact artifact
identities are in current project state. This qualification covers the exact
returned phase0 stop, not broader interrupted scale/recovery cases required by
K7/K10. The scale itself is still unqualified and requires a NEW scale intent.
