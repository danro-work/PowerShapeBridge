# Закрытие собственного сохранённого результата среди других окон

Когда собственный сохранённый Result находится перед другим открытым документом,
прежний профиль закрытия его отвергает: он квалифицирован только для последнего
окна. Новый экспериментальный профиль позволяет завершить именно этот Result,
сохранив остальные документы и их относительный порядок.

Флаг `ownedSavedFinalizationOrderedExperimental` по умолчанию выключен и требует
прежний `ownedSavedFinalizationExperimental` и его зависимости. Только полный
сервер публикует `execute_owned_saved_finalization_ordered` и
`verify_owned_saved_finalization_ordered`. Решение пользователя задаётся точным
`finalize_owned_saved_result_with_sealed_bytes_ordered_windows`.

Новый schema2 план фиксирует `windowOrderPolicy`: удаляется только собственная
активная цель, число окон уменьшается ровно на одно, тип/ID/имя/путь каждого
оставшегося документа и относительный порядок совпадают. Номера окон и native
window IDs могут измениться после закрытия; они не являются постоянными ссылками.
До и после требуется полный однозначный список с одной активной строкой.
Native и SDK независимо проверяют эту политику. Старый schema1 профиль сохраняет
проверку последнего окна и не принимает новый план.

Исполнитель общий: текущий saved-source, fresh context, защищённый seed/checkpoint,
однократный claim, fence, журнал и одна фиксированная команда закрытия. Claim
общий для обоих профилей, поэтому смена имени инструмента не разрешает повтор.
Меняться могут только байты собственного writer при сериализации закрытия;
исходный SaveAs-хеш остаётся историческим, новый fingerprint хранится отдельно.
Остальные сохранённые файлы и запечатанные копии должны совпасть точно.
Отдельный verifier требует авторитетный возврат, свежие наблюдения и matching
fence. При неизвестном результате повтор закрытия запрещён.

Это не общий close-all или разрешение закрывать пользовательские, несохранённые,
переименованные либо многовидовые документы. Сохранность списка и файлов не
доказывает полную топологическую эквивалентность всех открытых моделей.

Перед ранним испытанием прошли 17 Native проверок, 15 независимых Framework/SDK
сравнений политики, 10 SDK admission проверок, 36 Python config проверок, прежние
Native проверки финализации и STDIO-каталоги 99 full / 11 readonly / 97 при
выключенном новом флаге. Это готовность пакета, а не приёмка К8–К11.
