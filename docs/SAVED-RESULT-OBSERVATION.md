# Восстановление доступа к сохранённому результату

Статус: full-only MCP `restore_owned_saved_result` и отдельная подготовка дисковой копии прошли раннюю реальную проверку на уже сохранённом SOLID/mm. Native 0.44 установлен с резервной копией; SDK 0.50 проверен отдельным STDIO-клиентом. Обычный клиент остаётся на прежнем SDK. Геометрия, SaveAs, OPEN и закрытие в этом блоке не выполнялись; это ещё не приёмка полного v1.

Повторное соединение теряет краткоживущие SDK handles. `restore_owned_saved_result` принимает SHA первоначального успешного SaveAs verifier, свежий candidate handle и одноразовый выбор активного документа. Отдельный default-false флаг `ownedSavedResultRestoreExperimental` требует general-v1 и включённых guarded reopen, SaveAs, copies, candidates и bindings. Read-only сервер этот инструмент не регистрирует; схема принимает только четыре заданных строковых аргумента с проверкой формата ID/SHA.

Native проверяет исторические файлы и цепочку SaveAs до подключения COM, затем под executor lock использует retained-context `SavedResultObservation`. Проверяются тот же процесс/сеанс/документ, доступные свойства и единицы, WORLD, пустое выделение, два текущих чтения, окна и сохранённые файлы. Выход — новый frozen report со scope `current_saved_result_same_process_document_observation_v1`. Прежний журнал, claim и verifier не меняются; его исторический список окон не объявляется заново подтверждённым. Fake context остаётся unqualified. Флаги report `executionAuthority=false` и `sdkLeaseIssued=false` описывают Native доказательство.

SDK отдельно связывает raw response, frozen report, отправленные параметры, pinned inspection/listing и первоначальную успешную цепочку SaveAs. Непроверенный, поздний, отменённый или неизвестный результат не выдаёт handle. Успешный результат содержит connection-local `savedResultHandle`: это ограниченный доступ к сохранённым байтам для отдельной подготовки копии, без edit binding или OPEN authority. После истечения срока/закрытия соединения нужен новый явный restore; автоматически команды не повторяются.

`CurrentSavedResultSource` удерживает собственные file/directory pins, физическую identity и два SHA сохранённого файла, отдельный текущий срок и оригинальный successful verifier. Observation-as-original цепочки отвергаются до вложенного reader. Native `SavedReopenSource` явно различает исходный SaveAs и свежее наблюдение; старый `OwnedSavedSource` и его строгий контракт не ослаблены.

| Frozen reopen plan | Источник | Поля ссылки |
|---|---|---|
| schemaVersion 1 | Первоначальный successful SaveAs verifier | verificationRequestId / verificationReceiptSha256 |
| schemaVersion 2 | Qualified current observation | observationRequestId / observationReceiptSha256 |

Обе схемы имеют ровно 21 поле. Старые планы не переписываются; SDK и Native consumers явно проверяют версию и соответствующий источник. Подготовка не открывает документ: создаёт отдельные seed, working и read-only checkpoint с проверенными одинаковыми байтами и различными физическими identity. Поздний независимый verifier может читать исторические доказательства; этот режим не является новым разрешением OPEN.

Реальная проверка выдала новый SDK handle и подготовила schema2 копию. Независимые read-only/model/window и file/journal проверки подтвердили неизменность модели, 25 окон, 110 защищённых и 25 открытых сохранённых файлов; исходный verifier уже истёк и не продлевался. Два отказа внешнего квалификационного скрипта сохранены: сначала сравнивались служебные candidate-поля с raw Native entities, затем строки timestamps с разной точностью дробной секунды. Первый отказ был до restore; после второго результаты проверены как существующие артефакты без повтора успешных restore/preparation.

Целевые проверки: 73 .NET, 21 Native wire/config, 11 Python config; прежние 20 parser scenarios/68 checks и passive core qualification сохранены. Полный локальный .NET прогон: 935/936; единственный отказ был при лишней перезаписи изолированной тестовой конфигурации, до MCP. Фикстура теперь публикует ту же конечную настройку один раз; 22 целевые проверки, включая отклонённый случай, прошли. Первый полный прогон не объявляется зелёным. CI wrapper и исходники нового пути включены в `verify-sdk.ps1`.

Следующая контрольная точка завершена отдельным блоком Native0.44.1/SDK0.50.1: новая current-source observation/schema2 preparation, один guarded saved-result OPEN25→26 и отдельный verifier/new binding прошли. Независимые readonly/file/window/journal и восемь исходных WORLD точек подтвердили sampled persistence; SaveAs/scale не повторялись. [Квота Bridge](SAVED-REOPEN-WINDOW-QUOTA.md) сохраняет default20, расширение требует явного config и неизменного полного current-source window context. Старые frozen plans/исторические verifier не менялись. Полная топология, correspondence faces/UV, нормали и остальные типы/наборы не сертифицированы.
