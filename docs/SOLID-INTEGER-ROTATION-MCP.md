# Один SOLID: целочисленный поворот через MCP

Native0.42/SDK0.48 добавляют отдельный bounded experimental путь для поворота одного SOLID на целый ненулевой угол от −359 до +359 градусов. Тело должно быть единственным объектом собственной рабочей копии,документ — в mm/factor1,WORLD и с пустым выделением. Центр и направление оси задаются явно. Дробные углы,другие типы и наборы пока не поддерживаются.

## Рабочий процесс

1. Подготовить собственную saved-byte копию/checkpoint,один раз открыть и независимо проверить. Исходник защищён.
2. Получить свежие наблюдаемый набор и привязку собственного документа. `prepare_rotation_plan` создаёт пассивный план с явными углом,центром и мировой осью.
3. `prepare_owned_solid_rotation` закрепляет исходные face names/UV и читаемые точки/нормали; сохраняет preparation receipt и descriptor bundle. CAD не меняется.
4. `execute_owned_solid_rotation` расходует разрешение до отправки,затем существующий исполнитель вызывает один RotateItem. Результат остаётся unverified/fenced.
5. После новых inspection/listing `verify_owned_solid_rotation` независимо читает прежние pinned witnesses,проверяет receipt,исходные plan axis/angle,журнал,контекст,владение и файлы. Только полный успех завершает журнал и снимает matching fence. Unknown не повторяется и не компенсируется обратным поворотом.

Маршрут включается отдельным `ownedSolidRotationsExperimental`,по умолчанию false; требует general owned rotation/operation plans и их зависимости. Три quarter-turn tools,их flag/scopes и профили сохранены. Их leases нельзя обменять на разрешение общего поворота; общий permanent execution claim защищает исходный план и между маршрутами.

SDK использует общий транспорт/проверку доказательств с quarter-turn facade и отдельное хранилище разрешений. Регистрация: `ToolCatalog.Create` включает `SolidRotationTools.Create(session)`; `Program.cs` передаёт этот каталог в `.WithStdioServerTransport().WithTools(ToolCatalog.Create(session))`. Tools/параметры имеют Description/annotations и строгую JSON Schema. В read-only каталоге новых tools нет,прямые вызовы также запрещены до IPC. Legacy Python facade их не предоставляет.

## Численные критерии и пределы

До раннего CAD-теста задан профиль `solid_world_integer_rotation_mass_properties_v1`: face positions/normals abs2e-6,COG abs1e-5мм,raw volume abs1e-6+relative1e-6,прочие сравнения relative1e-9. Прежний ограниченный relative1e-9 добавляется к абсолютным бюджетам; остальные raw invariants сохраняют abs1e-6. Профиль записывается в immutable diagnostic/result и проверяется SDK; произвольный допуск через MCP передать нельзя.

Это engineering критерии сравнения,не заявление о точности API Autodesk. При смешивании трёх округлённых компонентов погрешность распространяется через матрицу вращения: для входной/выходной ошибки по половине1e-6 верхняя оценка .5e-6*(1+sqrt(3)) меньше2e-6. Это объясняет выбранный бюджет,но само по себе не доказывает точность измерителя. COG/volume остаются отдельными вычисленными свойствами.

Повернутый AABB исходной детали — консервативная оболочка. Для общего поворота проверяется прямое и обратное включение; равенство оболочки реальным габаритам не заявляется. Проверяются восемь прежних точек/нормали,COG,доступные raw invariants,файлы и контекст,а не полная топологическая эквивалентность. Неизвестные единицы площади не объявляются мм².

Целевые78 SDK/геометрических проверок и80 Native boundaries прошли до реального сценария; отдельно подтверждены16 general-route случаев после уточнения cross-route lease проверки. Native runner остаётся offline и требует собственного marker. Серверный CI включает отдельную general configuration. Реальный сценарий,независимый matrix/file audit,регрессия и discovery обычного Codex фиксируются в PROJECT-STATE.md и локальной карте. К8–К11 не завершены.
