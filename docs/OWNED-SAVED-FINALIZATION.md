# Close an owned saved Result while preserving a sealed output

`execute_owned_saved_finalization` and `verify_owned_saved_finalization` form a separate, full-server-only experimental profile. `ownedSavedFinalizationExperimental` defaults to false and requires current saved-result restoration, verified saved-reopen preparation and general owned context. The older byte-preserving saved-Result close stays disabled and unchanged in purpose. Its original unknown outcome is not repaired by this profile.

The new contract distinguishes the owned live writer A from the independent read-only seed B, unopened working derivative C and read-only checkpoint D created by the existing [pre-close preparation](OWNED-PRECLOSE-SEAL.md). B is the canonical immutable saved output. A may change its serialized bytes when PowerShape closes it; its path and physical identity must stay the same and its actual resulting hash/length are recorded separately. The old successful SaveAs fingerprint remains historical evidence of B's bytes, never a fingerprint of changed A.

Execution requires an observed saved-result handle from this MCP connection, fresh candidate/active-window choices, the exact disposition `finalize_owned_saved_result_with_sealed_bytes`, and the original successful seed-preparation receipt ID/SHA. Before CAD, the Native provider validates current A's original SaveAs history, the seed's frozen preparation/ownership/journal lineage, distinct file identities and all immutable saved bytes. The target must be its original named owned Result in one unique active-last window, with WORLD and empty selection. No arbitrary filename, command, save, close-all, inverse or retry is accepted.

The provider freezes a bounded plan, a once claim and a separate finalization fence, consumes CAD leases and sends the existing fixed close command once. It preserves B/C/D and all other saved files/windows. Only the already identified owned writer A is excluded from the unchanged-byte set; its actual post-close physical identity and stable double-read fingerprint remain mandatory. A command return is executed-unverified. A separate verifier rechecks the original receipt/claim/plan/journal return, fresh remaining context, unchanged protected files and the same finalized A fingerprint before appending success and releasing only that operation's fence. Unresolved finalization blocks saved-result restoration. Read-only inspection remains separate and available.

Frozen seed lineage can be checked after A changes without reopening the old live-A source proof or manufacturing a new SaveAs receipt. The SDK verifies raw receipts, exact plans/claims, journal/evidence, protected bytes and final fingerprints before accepting success. Both tools use explicit registration in `ToolCatalog`, strict schemas, full-only discovery and JSON-boolean dependency checks.

On 24 October 2026, Native 0.48 and staged SDK 0.54 passed one real finalization, separate verification, generic preparation from read-only B, one new generic OPEN and independent OPEN verification. Windows changed 26 → 25 → 26, preserving the other 25. Owned A changed from 819,200 to 790,528 bytes with the same physical identity. B/C/D retained their original saved bytes. The new copy opened from B preserved inventory, units, COG/raw mass properties, bounds and eight sampled XYZ points within the fixed 0.01 mm document tolerance. Independent file/window/journal and read-only checks passed. No SaveAs, geometry command, selection change or mouse action was performed in this block. This is a qualified narrow owned-Result workflow, not full topological equivalence or qualification for arbitrary document kinds.

The runtime update used staging, backup and one panel restart. Ordinary Codex remains SDK 0.48; the new tools were exercised through a real separate STDIO client. Readiness passed 24 isolated Native guards, 44 targeted SDK cases, 16 Python configuration cases and full64/read-only8 discovery with valid-shape refusals before Native. A review correction made SDK ownership hashing and parsing use the same bounded bytes; its 13 targeted cases then passed. Full local regression passed 999 of 1,000 cases: the unchanged advisory-report `File.Replace` test received `UnauthorizedAccessException` in the isolated environment, then passed separately with user-session access. The original full run is retained and is not labelled green. Exact-head publication checks are recorded in the current project state and local evidence.
