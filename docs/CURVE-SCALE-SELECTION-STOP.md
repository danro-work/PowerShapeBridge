# COMPCURVE scale: phase0 stop and passive evidence

Uniform scale of a COMPCURVE is **experimental and not yet qualified in CAD**.
The default-off `ownedCurveScalesExperimental` tools reuse the existing scale
plan, one-use claim, mutation fence, journal and fixed thirteen-phase NOKEEP
program. Only the explicit curve is targeted; the neighboring SOLID is a control.
The planned proof covers complete1..N controls, tangent directions/magnitudes,
free flags, observed ranges/length/raw area and unchanged neighboring SOLID.
It does not prove full topology. Scale persistence remains unverified.

The early real attempt stopped after phase0
`SELECT CLEARLIST ADD COMPCURVE '2'` returned. No phase1 `EDIT SCALE`, value,
APPLY, dismiss or clear command was submitted. The guard compared the command
type `COMPCURVE` with the actual native selection descriptor `Composite Curve`.
The corrected guard maps this one closed type; existing SOLID/SURFACE guards
remain exact. That correction alone is not a successful scale qualification.

The original failure receipt, once claim, four-event unknown journal and
matching fence are preserved. Neither a frozen phase0 record nor unchanged
observed metrics justifies deleting that fence or replaying the original intent.

## Why full curve data is pending

The installed Autodesk2023 `file/ole/data/IPshapeModelDoc.htm`, section
`GetCompCurvePointData`, documents error1 for no active model or nonempty
selection. The attempted selected-control reader really failed. The first
wrapper hid its nested reason; diagnostic0.63.1 exposed the getter refusal.
Neither failed request is considered a successful curve proof.

Native0.63.2/stagedSDK0.69.1 remove the unsupported selected-control path.
The public curve-layout and combined curve/SOLID readers still require empty
selection. Fake selected getters now refuse too, matching the documented
restriction instead of allowing an impossible real workflow.

## Separate passive stop observer

`inspect_owned_curve_scale_selection_stop` is explicitly registered through
`ToolCatalog.Create(session)` with `..CurveScaleStopTools.Create(session)`.
It is available only in the full server with a separate default-off
`curveScaleStopInspectionExperimental` gate, dependent on the curve-scale gate.
It has read-only/idempotent/non-destructive annotations; full-only visibility
does not grant mutation authority. STDIO, .NET10 and pinned SDK packages are
unchanged. Configuration/mode refusals occur before Native queue submission.

Inputs bind the exact original failure ID/SHA plus fresh inspection and active
listing handles. Native and SDK independently check the immutable preparation,
original source measurement, frozen command program, exact two phase0 files,
four-event journal, matching fence/claim, saved owned bytes and current context.
Two direct native selected-items/metadata reads must identify the exact original
curve composite/type/name/level. Non-selection observed properties/files/windows
must match. The original source control capture remains pinned as history.

Success is deliberately named
`owned_curve_scale_selection_stop_observed_pending_controls`, with profile
`owned_curve_scale_phase0_stop_pending_controls_v1` and
`fullControlProofAvailable=false`. No current control capture is returned.
Selection, original unknown journal, claim and fence remain unchanged;
`mutationAuthorityGranted`, `copyFenceReleased`, `originalOutcomeResolved`,
`geometryMutationAttempted`, `contextChangeAttempted`, `cadSaveAttempted` and
`fullTopologyEquivalent` are false. The observer executes no CAD command and
issues no recovery or general edit lease.

The changed profile passed early real MCP qualification on the already-owned
copy: positive native selected identity, unchanged observed properties,
14original proof artifacts,863protected files and28windows. An independent
Python audit and ordinary readonly Codex confirmed the observation. Full current
controls remain pending. Targeted Native4/Framework-SDK9/SDK16/Python28,
catalog85full/11readonly and legacy empty-reader10 passed. Post-CAD checks are
recorded in local project state. These counts do not establish scale success.

## Separate recovery block

The subsequently qualified narrow clear-only lifecycle is described in
[CURVE-SCALE-STOP-RECOVERY.md](CURVE-SCALE-STOP-RECOVERY.md). The observer still
grants no recovery authority and retains its pending-controls semantics. The
requirements below remain the safety boundary of that separate lifecycle.

Prepare a distinct, narrow recovery intent from fresh positive selection,
original stop evidence and current owned/file/window context. It may authorize
exactly one selection-clear command, never a repeat of phase0 or scale. Preserve
the original claim/fence while the recovery has its own one-use claim/journal.
Unknown recovery must stop without another clear, inverse or implicit cleanup.

After authoritative clear return, independently inspect empty WORLD and read
all original curve controls/tangents/magnitudes/free flags and pinned SOLID
samples. Only that complete successful proof may record a separate resolution
and release the matching fence; it must never label the original scale as
successful or erase its history. A new scale then requires a new intent and
fresh binding. It is not a replay of the consumed original intent. K8–K11 remain
open, including the remaining operation matrix and personal v1 acceptance.
