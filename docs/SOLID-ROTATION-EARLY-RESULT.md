# К8: ранний поворот тела и сохранённый результат

20 октября 2026. На собственной копии представительной детали с отверстиями и скруглениями выполнен один поворот одного SOLID на +90° вокруг WORLD Z через мировое начало. Отдельный COM-контекст проверил заранее закреплённые face/UV точки и нормали, COG, WORLD-габариты и доступные raw invariants. Затем через обычный MCP выполнены один SaveAs в новый файл и одно открытие отдельной копии результата. Прежние закреплённые точки/нормали и свойства сохранились после открытия.

Это первый ограниченный живой результат. Полная К8, универсальный поворот и К11 ещё не завершены. Геометрический executor/verifier вызывались из staging как библиотека через существующие ownership/lease/claim/journal/fence guards. MCP execute/verify для поворота и production queue route ещё не добавлены. Панель, установленный Native/SDK и настройки не обновлялись.

## Исправленный реальный дефект

Первая попытка остановилась до RotateItem: модель из реального COM-reader представлена анонимным CLR DTO, а guard ожидал Dictionary из JSON. `Stable` теперь нормализует обе проверки наблюдения через JSON, затем проверяет модель и владельца. Дополнительный regression case использует анонимный model DTO. Журнал, claim и fence первой отклонённой попытки сохранены; после исправления использованы новая собственная копия и новый план. Исходный request не повторялся.

## Граница подтверждения

`SolidRotationContext.ExecutionContext` разрешает callback не более одного раза даже после исключения или return0. Привязка тела/COM mapping, процесс, окно, WORLD и пустое выделение проверяются существующими guards. `ReadContext` не содержит Rotate. Descriptor сохраняет прежние face names/UV; после изменения ближайшая грань заново не вычисляется.

Обычный `OwnedRotationVerification.Verify` по-прежнему возвращает только `observed_rotation_samples_match_unqualified` и сохраняет fence. Внутренний `VerifyQualifiedSolidQuarterTurn` допускает завершение журнала и удаление только matching fence после всех прежних независимых проверок и дополнительных связей native-backed descriptor bundle с исходным планом. Его scope: ровно один SOLID, единственный объект документа, mm/factor1, +90°, WORLD Z через начало. Fake-backed reader не получает эту authority; другие углы/оси/типы не квалифицированы.

Наблюдения точек, нормалей, COG и invariants не доказывают полной топологической эквивалентности. Объём и площадь остаются в проверенных raw-единицах; неизвестные единицы площади не объявляются мм². Идентификаторы и face names не считаются устойчивыми после произвольного переоткрытия. Диагностика сохранённого результата требует точного совпадения прежнего descriptor и явной активной собственной копии; при отсутствии соответствия останавливается без поиска другой грани.

## Проверки

Целевые offline проверки: 25 executor scenarios с независимым аудитом 606 hashes, 15 verifier scenarios/497 hashes, 19 adapter checks. Они дополняют уже выполненный реальный сценарий. Независимый локальный аудит подтвердил одну команду поворота, terminal journals, сохранность прежних опорных измерений после открытия, исходника, 199 защищённых файлов и установленного runtime/config. Точные CAD-данные, пути и request IDs остаются в локальных evidence, вне публичного репозитория.

Диагностический reader `tools/ReadSavedPinnedSolidFaces.cs` загружает staging assembly как пассивную библиотеку и принимает путь ожидаемой активной копии, новый файл отчёта и исходный descriptor bundle. Он ничего не выбирает, не активирует, не сохраняет и не запускает worker Main. Для сборки/COM-чтения нужна действующая конфигурация наблюдателя; тестовые offline configs не заменяют установленную настройку единиц.

Следующий шаг — связать подтверждённый ограниченный сценарий с Native queue и обычными SDK MCP tools, сохранив короткие handles, read-only запреты и отдельную проверку результата. После этого отдельно расширять матрицу углов/осей/типов.
