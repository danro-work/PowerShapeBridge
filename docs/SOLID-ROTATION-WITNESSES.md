# К8: точки и нормали граней тела для проверки поворота

18 октября 2026. P0 принят пользователем. Добавлен и проверен в PowerShape
**пассивный провайдер измерений SOLID**. Это завершённый предварительный блок
К8; выполнение поворота через MCP ещё не включено и не принято.

`SolidFaceMeasurements.Capture` находит ближайшие грани к восьми углам
WORLD-габарита одного явного SOLID и закрепляет имя каждой грани и её UV.
`Read` читает положения и нормали только по этим сохранённым параметрам.
После изменения нельзя заново находить ближайшую грань или UV: это могло бы
сравнить другие точки и скрыть неверный результат. Дополнительно читаются COG,
доступные raw rigid invariants и WORLD-габарит.

Методы основаны на [руководстве Autodesk по макросам PowerShape](https://www.autodesk.com/sites/default/files/file_downloads/using_macros_with_powershape.pdf):
`solid[…].closest_face`, `surface[…].near`, `surface[…].evaluate`.
Нативные методы `Evaluate` и `RotateItem` сверены с установленной OLE-справкой
PowerShape 2023, `file/ole/data/IPshapeModelDoc.htm`. Поиск Autodesk Product Help
en_US не дал отдельного API-описания перечисления всех граней; статьи об UI
не используются как доказательство такого API.

Реальный `CLOSEST_FACE` может вернуть числовое имя. Декодер принимает строку
или конечное неотрицательное целое числовое значение; дроби, неверные типы,
небезопасные символы и диагностическую строку неизвестного параметра отклоняет.
Числовые векторы проверяются по размерности, типам и конечности.

В отдельном COM-контексте повторно прочитаны восемь закреплённых точек/нормалей
на шести гранях представительной детали, включая скруглённые грани, и COG.
Результаты совпали, выделение сохранилось. Провайдер ничего не выбирает и не
активирует. Guard исполнителя поворота по-прежнему требует пустое выделение;
пассивное чтение с сохранением выделения это требование не отменяет.

Целевые проверки: закреплённые UV после аналитического поворота, отсутствие
повторного поиска грани, смена контекста/mapping/единиц, нулевая нормаль,
выход точки за габарит, отсутствующие invariants, malformed arrays/имена.
21 проверка прошла; отказ без собственного fixture marker также проверен.
Регрессия Native в профиле rotation-plans: 524 checks, без подключения CAD.
Sandbox-прогон остановился на File.Replace собственного статусного файла;
с обычными правами пользователя те же проверки завершились успешно.
Запуск без CAD: `verify-solid-face-measurements.ps1`; он включён в `verify-sdk.ps1`.
Диагностический источник для реальных чтений: `tools/ReadPinnedSolidFaces.cs`.
Точные CAD-данные и журнал находятся только в локальных evidence.

Ограничения: это восемь опорных точек, **не полный обход граней**, не проверка
всей обрезки/отверстий и не доказательство топологической эквивалентности.
Площадь/объём остаются в raw-единицах. Знак/ось реального RotateItem,
MCP execute/verify, независимое разрешение matching fence и сохранённый результат
ещё требуют живого сценария. Установленные Native/SDK и конфигурация не менялись.
