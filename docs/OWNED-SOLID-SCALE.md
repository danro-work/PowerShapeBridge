# Owned SOLID scale — experimental route

Native0.43 / SDK0.49 provide three separate tools behind `ownedSolidScalesExperimental`, false by default. The flag requires general core, passive uniform-scale and operation-plan dependencies. Registration is explicit: `ToolCatalog.Create(session)` includes `..SolidScaleTools.Create(session)`; the class returns three `StrictTool` instances. No route is registered by the read-only server.

| Tool | Required connection-local inputs | Result |
|---|---|---|
| `prepare_owned_solid_scale` | `scalePlanHandle`, `workingDocumentBindingHandle` | New `ownedSolidScaleHandle`, pinned Native preparation receipt and membership bundle; no CAD change |
| `execute_owned_solid_scale` | Unconsumed `ownedSolidScaleHandle` | One frozen thirteen-phase recipe, `executed_unverified`, matching fence retained |
| `verify_owned_solid_scale` | Original execution ID/SHA, fresh candidate and active-document handles | Fresh independent reading; only the Native provider with complete matching proofs can finish its journal and release its fence |

The supported scope is one SOLID40, the only entity in its owned copy, WORLD/mm/factor1, positive factor0.01–100 except1, and an explicit bounded centre. The source must be observably closed, connected, watertight, trimming-valid, with zero open links. The [membership profile](SOLID-SCALE-MEMBERSHIP-VERIFICATION.md) governs transformed source XYZ, direct bounds, COG and raw mass-property scaling. Face names/UV may change. Unknown metric-unit observations stay raw; no full topology, normal correspondence or persistence claim.

The disabled passive packet remains unchanged and cannot authorize execution by itself. The qualified bundle binds its SHA, source inspection, ownership/checkpoint/saved bytes, window digest and measurements. The SDK pins the raw preparation receipt in its own store, consumes both intent leases before submission and revokes CAD leases. Passive or rotation handles cannot authorize this route. Timeout/cancellation after submission is unknown and cannot trigger a retry.

The fixed recipe is SELECT explicit SOLID, EDIT SCALE, NOKEEP, UNIFORM, LOCK X/Y/Z OFF, SCALEORIGIN, centre, VALUE factor, APPLY, DISMISS, SELECT CLEARLIST. Parameters are validated and formatted invariantly; no public raw command input exists. Each phase has a lightweight retained-context guard and immutable started/returned SHA chain under a frozen plan and one-use claim. Failure stops immediately and retains the fence; no automatic CANCEL, DISMISS, inverse, WORLD or selection cleanup follows an uncertain phase.

Independent verification requires the exact complete thirteen-phase chain, original receipt/claim/fence and original source bundle. A fixture or math-only result cannot release a fence. Split research executions and other scopes are refused. Saved working bytes, checkpoint and all originally open saved files must remain unchanged. Save/reopen qualification is separate.

## Qualification boundary

Native fake-callback checks cover interruption at every phase, no replay, locale-independent commands and an independently measured result that remains fenced for a fake provider. SDK checks cover explicit flags/dependencies, read-only exclusion, pinned receipt/bundle, separate leases and refusal before submission. Full/read-only STDIO discovery was checked on the staged SDK.

One real half-scale case now passed through the staged SDK0.49.3 / installed Native0.43.3 route on the existing owned SOLID copy: one thirteen-phase intent, a separate Native verifier, read-only confirmation and an independent math/phase/file audit. Transformed source membership, direct bounds, COG and raw s²/s³ laws passed the declared profile; the matching fence was released. Source/checkpoint/working disk bytes and all currently open saved files were preserved. The result remains unsaved. This qualifies that one WORLD/mm half-scale case; other factors, entity types/sets and saved-result persistence remain separate qualifications.

Its preceding OPEN had timed out without `command_returned`. The separate [owned-document adoption and reconnect](OWNED-OPEN-ADOPTION.md) established current access without replaying OPEN or modifying its historical unknown journal. Two early preparation refusals found an incompatible saved-file sharing mode and wrapper diagnostics overwriting the passive receipt's read count. The working byte pin and distinct wrapper diagnostics fix these defects while SDK assertions remain strict. Both refusals and unclaimed passive artifacts were retained; no scale command had been submitted before the successful final intent. No completed research scale was replayed.
