# Переключение существующей системы координат через MCP

Статус на 16 октября 2026: Native 0.36.0-dev установлен с резервной копией
и одним перезапуском панели. Изолированный SDK 0.42.0-dev прошёл реальный
сценарий включения существующей системы и отдельного возврата WORLD.
Каждая операция независимо проверена; отдельный COM reader и файловый аудитор
подтвердили итог. Постоянный коннектор Codex на этот SDK не переключался.
Предыдущая ранняя проверка прямого API: WORKPLANE-SWITCH-QUALIFICATION.md.

Четыре инструмента регистрируются явно через
`OwnedWorkplaneActivationTools.Create(session)` в `ToolCatalog.Create`:

| Инструмент | Назначение |
|---|---|
| prepare_owned_workplane_activation | Подготовить существующую workplane по свежему typed candidate либо явный WORLD; CAD не меняется |
| execute_owned_workplane_activation | Использовать подготовку один раз и выполнить ровно один setter |
| verify_owned_workplane_activation | Независимо проверить исходную операцию по свежим чтениям и освободить только её fence |
| adopt_owned_workplane_activation_execution | После переподключения проверить исходные доказательства и получить только доступ к проверке |

Все четыре инструмента доступны только полному SDK-серверу при явном
`ownedWorkplaneActivationExperimental=true`. Отдельный read-only сервер их не
регистрирует. Его существующая диагностика восстановления читает записанные
доказательства этой операции без CAD, записи файлов или разрешения повтора.

Включение системы и последующий WORLD — разные одноразовые операции. Выбранная
система остаётся активной после успешного включения. Подготовка отвергает уже
активную цель. Имена, команды, пути и числовые CAD ID не принимаются от клиента.
Ссылка кандидата должна обозначать WORKPLANE из того же чтения, что и binding.
Это не расширяет допустимые типы геометрических entity sets.

Первый исполнитель ограничен одной SOLID и одной WORKPLANE, пустым выделением
и исходным WORLD либо этой единственной системой. Полная матрица общего v1,
включая несколько систем, типы/наборы и пять классов моделей, остаётся открытой.
Начало/оси, прямые WORLD-габариты, прочие свойства и файлы должны сохраниться.
COG проверяется с ожидаемым преобразованием базиса; raw-единицы не переименовываются.
Габариты и свойства не доказывают полной топологической эквивалентности.

Исходные intent, execution, once claim, setter-return и журнал неизменяемы.
После неизвестного исхода нет повторного setter, автоматического WORLD, Undo,
сохранения или восстановления. Без подтверждённого setter-return независимая
проверка не может объявить успех. Подтверждённый возврат с последующей ошибкой
чтения допускает отдельную проверку без повтора команды.

Проверки до живого сценария: 14 native случаев, 14 SDK unit/protocol случаев,
SDK/native STDIO с отдельными включением/WORLD и reconnect, потеря ответа и
отмена после имитированного эффекта; отдельные файловые аудиторы обоих путей.
Эти проверки не подключаются к CAD. После реального блока полная локальная
регрессия прошла: 790 .NET-тестов без ошибок/пропусков, native-проверки,
совместимость артефактов, STDIO и Inspector. CI фиксируется отдельно по SHA
ветки; весь К8–К11 этим результатом не принимается.

`tools/audit_live_workplane_activation.py` отдельно сверяет исходные native
ответы, планы/once claims, цепочки двух журналов и фактический порядок
«независимо проверенное включение → команда WORLD», преобразование COG,
итоговое чтение, 67 защищённых файлов и frozen package. CAD не вызывается;
исходные доказательства не исправляются. Файловые контроли явно помечены как
синтетические и не считаются новой живой проверкой.

Основание поведения WORLD/активной системы:
[Autodesk PowerShape 2023: activation](https://help.autodesk.com/view/PWRS/2023/ENU/?guid=GUID-517690AC-57AF-4BBB-86BC-A26F45FDD068).
Семантика COM-getters подтверждалась отдельно ранним реальным сценарием.
