# Правила работы над PowerShape Bridge

Этот файл предназначен для корня `D:\ChatGPT\PowerShapeBridge\PS_Bridge`. Если там появился AGENTS.md, объединить инструкции, не перезаписывать его вслепую.

- Сначала универсальный рабочий MCP v1; технологический модуль — отдельный следующий продукт и клиент MCP. Не внедрять материал, W/h/k, Z-stop, ОТМ/ТМ и технологические правила в общее ядро.
- Продолжать авторизованную разработку автономно. Перед использованием мыши запрашивать согласие пользователя. При отсутствии нужного доступа сообщить конкретное ограничение.
- Перед изменением CAD прочитать активную модель и проверить ожидаемый процесс/документ/контекст. Автономность разработки не означает автоматический запуск мутационных self-test на активной пользовательской модели.
- Сохранять отдельный режим/сервер чтения. В нём не выполнять выделение, активацию, сохранение, геометрические операции или создание screenshot.
- Исходные STEP/psmodel и квалификационная базовая модель защищены. Тестовые изменения выполнять на явно принадлежащих испытанию рабочих копиях. Checkpoint отделять от активного изменяемого файла.
- При неизвестном результате изменения не повторять команду автоматически. Сначала журнал и независимая проверка; результат обозначать как неизвестный до установления фактов.
- Закрывать только окна, принадлежность и ненужность которых установлены. Не сохранять изменения в закрываемых тестовых копиях без необходимости сценария; при неизвестной принадлежности или данных пользователя остановиться для уточнения.
- Не считать PID, номера окон и ссылки из прошлого чата актуальными. Повторять чтение после переключения/переоткрытия/переподключения. Ссылки P2.21 для чтения нельзя использовать как принятые ссылки изменения.
- Не переименовывать `releases\P2.6`: это совместимый путь текущих компонентов. Не запускать вторую панель/worker и не обновлять исполняемые файлы при незавершённой очереди.
- Собирать в staging, не поверх корневого launcher. Проверять скрипт развёртывания перед запуском: он закрывает панель и обновляет runtime; перенос документов этого не требует.
- Подтверждённые, экспериментальные и планируемые возможности разделять. Габариты/COG/объём/площадь не являются доказательством полной топологической эквивалентности. Raw-единицы не выдавать за мм или мм² без проверки.
- Для технологического модуля: все контуры одного исходного слоя/элемента экспортировать в один DGK, например `1:Vneshnie 0.6` → `1-Vneshnie 0.6.dgk`.
- Для пакетных сечений предпочитать измерение диапазона → комплект секущих → одно пересечение двух явных наборов → проверка всех кривых → удаление только собственных временных объектов. Универсальность принимать отдельно.
- Источник текущего состояния: PROJECT-STATE.md, затем актуальные контракты, код и доказательства. Устаревшие разделы P0/P2.21 не принимать за текущие возможности.
- Запускать необходимые проверки по изменению и сохранять доказательства. Обновлять состояние и план после завершённого блока, перечисляя ограничения.
- Основной цикл по указанию пользователя: небольшая операция → ранняя проверка в PowerShape на собственной рабочей копии → независимая проверка результата → необходимые регрессионные тесты. Синтетические тесты сохранять, но не подменять ими работающий реальный процесс. Перед ранним CAD-тестом выполнять целевые проверки изменённого кода и готовности пакета; полную регрессию/CI проводить после законченного блока. Правила согласования CAD-изменений, защиты источников и запрета повтора неизвестного результата сохраняются.
